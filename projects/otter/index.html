Four Claude models, one otter

The prompt

One sentence, eight requirements

Each model got exactly this prompt, once, with no follow-up. It may read like a joke, but every phrase adds a constraint the model has to satisfy at the same time.

create a low poly 3D otter drinking coffee and using wifi in a swedish train station in a seamless loop using Three.js

This prompt and the idea of the test are inspired by Ethan Mollick's otter test. He repeats the same otter request with every new AI model to show how fast their abilities develop. See The recent history of AI in 32 otters →

Low poly

A style where everything is built from a small number of flat-coloured triangles, like folded paper or early 3D games. There are no smooth curves and no photo textures, so the otter has to be recognisable from a handful of simple shapes.

3D

The scene has real depth. A virtual camera looks at it, lights cast shadows, and the viewpoint can move without the picture falling apart. This is different from a flat drawing or a video.

Three.js

A free JavaScript library that draws 3D graphics inside a web page. There is no 3D editor and no ready-made model. The model must write code that places every shape, colour and light by number, and the result runs in any browser.

Drinking coffee

An action, not a pose. We should see a cup, steam and a paw that lifts the cup to the mouth and puts it down again.

Using wifi

Wifi is invisible, so the model has to decide how to show it. Typical answers are a phone in a paw, pulsing signal arcs and the familiar wifi sign on a wall.

Swedish train station

This asks for local detail: platform, tracks, a train, snow, station signs and departure boards with Swedish words. A generic grey platform does not count.

Seamless loop

The animation has to end exactly where it begins, so it can play forever with no jump, like a GIF that never stutters. Every moving thing must come back to its starting position at the same moment.

Otter

Not a bear, not a cat. An otter has a long body, a thick tail, small round ears and whiskers. A model that has never seen the result has to get this across in blocks and triangles.

Why this test

Silly on the surface, demanding underneath

Why it is interesting

  • You can see the result.Most model comparisons are tables of scores. Here anyone can press play and judge in ten seconds whether it works.
  • It tests many skills at once.Spatial reasoning, programming, art direction, animation timing and general knowledge about otters and Sweden all have to line up in one file.
  • There is no single right answer.Four models make four different otters, stations and camera angles. The differences show taste and priorities, not only correctness.
  • It is hard to memorise.Nobody has a stored answer for this exact combination, so the model must build it from scratch.
  • Failures are easy to spot.A floating paw, a jump at the loop point or an otter that looks like a potato is obvious to a non-expert.

Why it is challenging

  • The model works blind.It writes numbers for positions, angles and colours and cannot look at the picture while writing. A paw that is 0.2 units off ends up inside the head.
  • Everything is built from code.An otter body, a train and a departure board all come from geometry and canvas drawing written by hand in one file.
  • The loop is maths.Each motion needs a whole number of cycles per loop. One careless speed value and the animation visibly jumps when it restarts.
  • Low poly leaves nowhere to hide.With only a few shapes, each choice of proportion decides whether it reads as an otter or as a brown blob.
  • The requirements compete.More detail costs performance and code length. More motion makes the loop harder to close.
  • Library details matter.Three.js changes between versions. Using the wrong function name or colour setting can break the page or wash out the colours.
